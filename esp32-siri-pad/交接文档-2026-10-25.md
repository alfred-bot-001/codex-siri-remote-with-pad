# Siri Voice Pad 开发交接（2026-10-25）

## 项目现状

当前目标硬件是 **Waveshare ESP32-S3-Touch-LCD-3.5**，搭配 Apple Siri Remote A2854；此前的 5 寸 ESP32-P4 板已退货，仓库中的 `esp32-p4-siri-pad/` 仅作历史参考。S3 固件以 480×320 横屏运行，通过蓝牙接收遥控器按键与语音，通过 USB 向 Mac 提供 HID 键盘、UAC2 麦克风和 CDC 诊断接口。当前功能代码基线为 [`218694a`](https://github.com/alfred-bot-001/codex-siri-remote-with-pad/commit/218694aff9a754cceab1f2eedc5086a2fd26e411)，位于仓库 `main` 分支；本交接文档不代表对设备重新刷机。

截至 2026-10-25，本机仍识别到序列号 `1020BA4658B4-PAD1` 的 Pad CDC 设备；Mac 的 `local.siri-voice-pad.weekly-quota` LaunchAgent 正在运行，最新日志发送 **Codex 100、Claude -1**。Claude 最后一次有效缓存来自 10 月 21 日，已过一小时有效期，所以 Pad 显示 `--` 是当前设计下的预期结果。设备内已刷固件与 Git 提交的逐字节对应关系没有独立版本标识可核对；10 月 21 日的构建、刷写和设备帧缓冲截图已有记录，今天只重新构建和运行主机测试，**没有刷机**。

## 已实现的交互

| 输入 | 默认行为 |
| --- | --- |
| 遥控器语音键按住／松开 | 按住／释放右 Option，同时启停遥控器麦克风到 USB 音频流 |
| 屏幕橙色麦克风点击／再点击 | 按住／释放右 Option，同时启停板载麦克风 |
| 圆盘中键 | 回车 |
| 遥控器减号／加号 | 光标左／右，可保持按下；屏幕左右箭头也可操作 |
| 播放／暂停 | 空格，可保持按下；屏幕空格按钮也可操作 |
| 圆盘左／右 | `Control+Option+Command+G` 唤起或隐藏 ChatGPT；`Control+Option+Command+C` 唤起或隐藏 Claude |
| 小电视键 | `Command+空格`，调用 Mac 的输入法切换快捷键 |
| 屏幕 Chrome 按钮 | `Control+Option+Command+B` |

以上为默认映射；Pad 设置页可修改八个已识别遥控器按键的映射，并将设置保存在 NVS。ChatGPT、Claude、Chrome 的组合键须在目标 Mac 上预先配置，Pad 只发送键盘事件，不知道应用是否真的打开或正在运行。设置页还提供蓝牙搜索、连接管理和息屏时间；息屏默认 30 分钟。语音键优先使用遥控器麦克风，屏幕麦克风才使用板载麦克风。USB 断开、遥控器断连或音频中断时会释放语音修饰键；重新连接不会自动开始录音。

首页左侧竖排 ChatGPT、Claude、Chrome，右侧是板载麦克风，底部有方向键、空格、回车和状态栏。设计源文件是 [`design/weekly-quota-landscape.html`](design/weekly-quota-landscape.html)，10 月 21 日读取的设备帧缓冲截图是 [`design/device-weekly-screen.png`](design/device-weekly-screen.png)。旧版竖屏图 `assets/pad-layout.png` 不是当前界面。

## 额度数据链路

Mac 端 [`tools/weekly_quota_bridge.py`](tools/weekly_quota_bridge.py) 每两分钟通过本地 Codex App Server 的 `account/rateLimits/read` 查询额度，按 `windowDurationMins == 10080` 找七天窗口，不假定它固定在 `primary` 或 `secondary`。Claude 来自 [`tools/claude_statusline.py`](tools/claude_statusline.py) 接收的 Claude Code `statusLine` JSON 中 `rate_limits.seven_day.used_percentage`；缓存仅保存剩余百分比、接收时间和重置时间。桥接器经 USB CDC 发送 `Q <Codex> <Claude>`，`-1` 代表未知；Pad 在 15 分钟没有收到桥接更新时也会清空两个值。

**尚未解决的主要问题：Claude 桌面版的“用量”页面不会触发 CLI 的 `statusLine`。** Claude Code 会话未提供七天字段，或上次有效字段已超过一小时，桥接器就发送 `-1`。10 月 21 日曾在已登录的 Claude Code CLI 会话中取得剩余 91%，并在桥接日志中看到发送成功；截至本次交接，该缓存已过期。下一步如需持续显示 Claude 额度，应先确定可靠、可维护的刷新来源，再做后台更新；不要把过期数字伪装为实时数据，也不要未经权衡就定时发送模型请求消耗额度。

本机部署位置：LaunchAgent `~/Library/LaunchAgents/local.siri-voice-pad.weekly-quota.plist`；日志 `~/Library/Logs/SiriVoicePad/weekly-quota.log`；Claude 缓存 `~/Library/Application Support/SiriVoicePad/claude-weekly.json`。安装脚本 [`tools/install_weekly_quota_bridge.py`](tools/install_weekly_quota_bridge.py) 会备份并修改 `~/.claude/settings.json` 的 `statusLine`；若已有其他自定义状态行，它会拒绝覆盖。换 Mac 后要分别安装桥接器并设置应用快捷键。

排查时先运行 `launchctl print gui/$(id -u)/local.siri-voice-pad.weekly-quota` 和 `tail -n 20 ~/Library/Logs/SiriVoicePad/weekly-quota.log`。桥接进程启动后一直没有记录 `Pad connected` 时先查 USB CDC 枚举；日志写 `Claude -1` 时先查 Claude 数据来源；日志持续有有效值而屏幕仍为 `--` 时再查 CDC 发送、设备重连和固件解析。Claude 缓存的 `received_at` 超过一小时即无效，不能仅凭旧日志里出现过有效百分比判断当前可用。

## 刷机与排障边界

[`tools/upgrade.py`](tools/upgrade.py) 仅适用于这块已核对的 S3 板：它先检查固件 CDC 的 VID/PID `0xCAFE/0x4015` 和序列号，再核对下载模式芯片 MAC `10:20:ba:46:58:b4`，只刷应用分区 `0x10000`，保留 NVS。脚本的默认 macOS 串口路径是旧现场值；10 月 25 日设备 CDC 实际路径为 `/dev/cu.usbmodem1412404`，**不能直接照抄默认路径**。若板子刷过其他项目，先备份 Flash、核对分区表，再按 README 的完整恢复流程处理；不要全片擦除配对数据。本机忽略目录 `backups/` 有历史备份，未上传 GitHub。

CDC 诊断命令在 README 中列出。黑屏但程序仍工作时可先用 `D` 读状态、`V` 复位屏幕并重绘；`B` 会进入下载模式，不能当普通重启键。曾出现界面锁长时间占用导致触摸无响应，当前固件以独立心跳监测在停滞超过 10 秒后重启恢复，但根因未彻底确认。此前遥控器录音复测中蓝牙丢包和解码错误为零，内部 FIFO 丢弃计数仍增加；不能据此直接判断可听断音或完全没有断音。

下一位开发者建议先处理 Claude 额度的可靠刷新，再做当前横屏固件的 Mac 端快捷键、两种麦克风及长时间稳定性验收，并记录固件版本／哈希以便以后核对设备和源码。现场录音、Flash/NVS 备份、个人配置与账号凭据不应提交到公开仓库。
